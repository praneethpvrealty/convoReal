# Codebase Refactoring Audit

A ranked list of the places where the codebase has outgrown its own rules, with the measurements that put each one on the list. Re-count before acting on a number; every figure here drifts with each feature.

The first audit (early 2026) named three items. All three shipped: the WhatsApp send-and-persist logic lives in `src/lib/whatsapp/meta-api-dispatcher.ts` and the automation, flow, reminder and broadcast callers are thin wrappers over it; `src/app/api/whatsapp/webhook/route.ts` is a 130-line entry point; currency formatting has a home in `src/lib/currency-utils.ts`. The complexity moved rather than disappeared, which is what the list below records.

## Open, in order

| `src/components/inventory/property-share-dialog.tsx` | 3,659 |            |                           |

The showcase view and the share dialog have no sibling test; the other three gained structure and render tests in `release/god-components-1`, and their page-load reads are on react-query. The property form's edit state and sections are done (`release/property-form-state`); its read-only view is still inline. The contact detail's unbounded reads are bounded (`release/contact-detail-reads`); its property list stays unbounded in rows until the property pickers search on the server. What remains: the property form's read-only view, and the remaining action-time reads. 24 client files still hand-roll the effect-plus-fetch-plus-state triple the handbook forbids.

### 2. Web and mobile each own the same query

Mobile holds 183 direct Supabase reads across 52 files. The contacts list now selects through `src/lib/contacts/list-columns.ts` on both surfaces; the query bodies are still written twice (`src/lib/contacts/list-queries.ts` versus `mobile/app/(app)/(tabs)/contacts.tsx`), and mobile's list carries no account filter, count or paging. Next: give the contact detail and agent detail the same shared column spec, then move the list query body behind an API route both surfaces call.

### 3. Chatbot engine

The draft-session half is done (#1217). `src/lib/ai/chatbot-engine.ts` is still about 4,700 lines, almost all of it one 3,500-line `processOwnerChatbotMessage`, with 27 inline queries on contacts, properties, messages, tags and notes and no test of its own beyond the structure checks. Next: move the contact and property writes behind repositories the same way, then split the owner flow by section (property session, contact session, new session) the way the inbound chain was split into steps.

### 4. Typing

147 `as unknown as` casts, 147 casts to `Record<string, unknown>`, and 53 explicit-any suppressions. Generated types now exist (`src/types/database.types.ts`) and three repositories use them; the shared clients are still untyped. Typing them surfaces, measured: `supabaseAdmin()` 162 errors in 62 files, the browser client 103 in 45, the request-scoped server client (through `AccountContext.supabase`) 111 in 61. Most come from `src/types/index.ts` disagreeing with the schema: fields it calls non-null that the database allows null (about 30 per client), literal unions over plain text columns, and `Record<string, unknown>` update payloads. `Contact` and `Deal` now agree with their generated rows: every column the database allows null is nullable in the hand type, the plain-text columns (`classification`, `status`, `lead_temp`, `feedback_status`, `buyer_alerts_consent`, `salutation`, `preferred_language`, `preferred_update_channel` on contacts; `status`, `brokerage_type`, `tds_status`, `deal_position` on deals) are `string`, and `created_at` / `updated_at` are nullable. Measured before the change: 70 of `Contact`'s properties differed from the row, 25 in type (23 on null or a literal union, 2 jsonb columns the hand type refines on purpose) and the rest only in being optional, which partial selects need; 31 of `Deal`'s differed, 11 in type. Fixing them surfaced 27 compile errors in 11 web files and 9 in 2 mobile files, all handled with `?? ''`, `?? undefined`, `=== 'fixed' ? 'fixed' : 'percentage'`, and `.find` over the known values rather than casts, and 10 `as` casts that the wider types made redundant came out. `src/types/contact-deal-schema.test.ts` fails the type check if either type drifts from the generated row. The known values stay as `DealStatus`, `BrokerageType`, `DealTdsStatus`, `DealPosition` and `UpdateChannel` where code relies on them. Still open: `as unknown as` is 148 and casts to `Record<string, unknown>` 136 outside tests (unchanged, because they sit on untyped clients whose results are `any`), and `Property` is not reconciled. Next: reconcile `Property`, then type one client at a time.

### 5. Smaller items

- Nine client files under `src/app/(dashboard)` exceed 800 lines, and `calendar/page.tsx` is a 2,110-line page file rather than a server page wrapping client content.
- Each chain step still writes its own Supabase queries; the next pass on `src/lib/whatsapp/inbound/chain/steps/` is to give the biggest steps (lead-conversation, lead-question, specific-property-interest, shared-contacts) their own unit tests over a stubbed context.
- Seven single `count: 'exact'` calls remain in browser code, each on an action rather than a page load (the inventory star cap, pipeline deletion, audience sizing, journey sheets). The mobile dashboard still issues eight on load; fold them into one aggregate the way the web dashboard did in migration 169.
- Avatar initials still follow four rules. `getInitials` (`src/lib/format/text.ts`) takes the first letters of the first two words and falls back to `?`; `initialsOf` in `team-workload.tsx` and the inline copies in `active-users.tsx` and `property-matches-tab.tsx` split on any whitespace and fall back to `A`, `U`, `C` or the phone; `deal-card.tsx` shows one letter; mobile's `initials` (`mobile/lib/format.ts`) takes the first and last word, so a three-word name reads differently on the two surfaces. Pick one rule before folding them together.
- `src/lib/whatsapp/` holds 105 files flat, thirteen of them `template-*`. Subfolders for templates, digests and inbound handlers, done alongside item 1.
- 1,467 bare `console.error` calls and no logger.

## Measuring again

```bash
# largest non-test files
find src -type f \( -name '*.ts' -o -name '*.tsx' \) ! -name '*.test.*' -exec wc -l {} + | sort -rn | head -40
# exact counts in browser code
grep -rn "count: 'exact'" src/components src/hooks src/app --include='*.tsx' --include='*.ts' | grep -v '/api/' | grep -v '\.test\.'
# rupee formatters outside the shared module (should be the price-band and masking helpers only)
grep -rnE "(function|const) [a-zA-Z]*(Inr|INR|Rupee|Price|Budget)[A-Za-z]*\s*(=|\()" src mobile/lib --include='*.ts' --include='*.tsx' | grep -v '\.test\.' | grep -v 'src/lib/format/currency.ts' | grep -iE "format|label"
# routes still off the shared auth helpers (should be the lint exemptions only)
grep -rl "auth.getUser()" src/app/api --include=route.ts
```
